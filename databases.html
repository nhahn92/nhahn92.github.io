Databases Narrative

The artifact I selected for the Databases category is the enhanced database layer of the Travlr Getaways application, originally created in CS‑465: Full Stack Development I. This part of the project includes the MongoDB schema, validation rules, sanitization logic, and the Express API endpoints that interact with the database. I chose this artifact because it demonstrates my ability to work with real database structures, enforce data integrity, and improve how information flows between the client and server. It also reflects the type of work I expect to do in IT and cybersecurity roles, where secure data handling and predictable database operations are essential.

I included this artifact in my ePortfolio because it shows how I transformed the database layer by improving validation, adding sanitization, refining error handling, and implementing aggregation pipelines. These enhancements made the application more reliable and more secure. They also demonstrate my skills in designing predictable data flows, preventing malformed input, and ensuring that the database returns consistent and meaningful results. The improvements I made highlight my ability to work with schemas, enforce structure, and build server‑side logic that supports a full‑stack application.

The process of enhancing this artifact taught me how important it is to think carefully about how data enters and moves through a system. One of the challenges I faced was understanding how the original project handled validation, since some fields were loosely defined or not validated at all. I had to redesign the schema so that each field had clear requirements and constraints. This required reviewing the existing data, identifying inconsistencies, and determining what rules would best support the application’s needs.

Another challenge was improving error handling and sanitization. The original code did not always provide clear messages when something went wrong, and some inputs were not sanitized before being stored. I updated the API so that errors were descriptive and helpful, which makes debugging easier and improves the user experience. I also added sanitization to prevent unsafe or malformed data from entering the database. These changes helped me better understand how secure coding practices apply to real applications and how small improvements can significantly reduce risk.

Through this enhancement, I met course outcomes related to using innovative techniques and tools in computing practices, especially in the context of database design and server‑side development. I implemented solutions that deliver value by improving reliability, structure, and security. I also met outcomes related to developing a security mindset, since the enhancements focused heavily on validation, sanitization, and reducing potential vulnerabilities. I did not fully meet outcomes related to algorithms in this enhancement, since those were addressed in a separate artifact.
